## Speed rule
- Must feel smooth at high refresh rate.
- Animate only `transform` and `opacity`. No looping blur. No stacked effects.
- Test performance in a browser before saying it's done: `node tools/kit.mjs perf` (main-thread ms per step, 4x slower CPU; `--file old.html` for the before).
- No scroll-linked motion on list rows (v308, #469 item 6: Played's rows rose, slid and drifted with `view()` timelines, four GPU layers each the whole time; they simply appear now). Start-up redraws go through `bootRedraw(name)` (runs once when the page has loaded, v308); never read a hidden screen's layout (a rect inside a `.panel:not(.on)` forces a full layout of that screen even under content-visibility): measure with a ResizeObserver (`lfRO`) or when it shows.
- Loops keep running while a finger moves (v282, the owner: "I dont want animation to stop while scrolling"). v280's hold (pause every endless loop mid-scroll) is gone: pausing/restarting cost 20–43ms as each scroll started and stopped (a visible hitch, and Nexi/the rail looked frozen), while running transform/opacity loops cost ~0.3ms of style per scroll frame. Never bring a scroll hold back; keep every endless loop transform/opacity only. `node tools/kit.mjs smooth` (in `all`, every PR) fails if Nexi's or the rail's loops stop mid-swipe, a loop running mid-swipe animates anything else, or what the finger landed on moves (#309). Measure scroll cost with `tools/scenarios/trace-loops.mjs` (`CPU=1`, `TAB=lib|game`).

## Hard-won rules (details and the story behind each are in docs/LOG.md)
- Many functions are wrapped by later scripts (`renderHome`, `save`, `gdMarkup`… see docs/MAP.md; screen changes use hooks instead): never read state off a function (`fn.x`, v198), extend a `const` instead of reassigning it (v216), and don't call a function that lives inside another script's scope (v237). New code goes in the last `<script>`/`<style>`.
- Never read layout (rects, scrollTop, computed style) right after an innerHTML redraw: do it in requestAnimationFrame or let an observer report it (v206). A check since Oct 20 (broken 12+ times as a written rule): `node tools/where.mjs --list-v206` finds a read after an innerHTML/outerHTML/insertAdjacentHTML/replaceChildren write in one function, also through a top-level helper, a setTimeout under 100ms or an `extend()` after/map hook; the audit's `layoutAfterHtml` budget (so every PR) fails when the count goes up. It can't see a read on a hidden screen (still yours to avoid) or a write made by a helper.
- Give classes unique names: grep `\.name\b` before adding one (clashes: .aw v164, .dash v195, .pl v204, .plat v228, shx-<k> v210).
- A `fill: "forwards"` animation must be cancelled on every path that ends it (v215). No `zIndex` in keyframes (v168); no filter/clip-path/mask on spinning layers (v167).
- Don't debounce idle work on "any DOM change": filter the mutations or cap the wait (v202).
- The page has no doctype (quirks mode): `$("#id")` uses getElementById; don't add a doctype without a full layout sweep (v219).
- Colours: `var(--volt)` / `rgba(var(--vrgb), a)`, never hex (v181); new UI uses the `--u-*` tokens, no italic/uppercase headings (v188). No native date inputs (v180).
- Bookkeeping that changes on every open/exit goes in its own localStorage key, not `S` (else the cloud backup re-uploads, v211/v212). `save()` is deferred; use `saveNow()` when the result matters (v169).
- Copying CSS: never filter lines (multi-line rules break); share a selector with `:is()` (v218).
- `worker/helper.js`: before pushing, copy it to a `.mjs`, run `node --check` AND import it in Node, and exercise changed routes with a fake `env` (v208 fix, helper v16).
